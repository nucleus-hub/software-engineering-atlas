# Case Studies

Work through end-to-end designs of well-known systems. For each, follow the
method in [`../fundamentals.md`](../fundamentals.md) and always close with
**trade-offs**.

## Suggested case studies
- URL shortener (TinyURL)
- Pastebin
- Rate limiter
- News feed (Twitter/Facebook timeline)
- Chat system (WhatsApp/Slack)
- Notification system
- Web crawler
- Search autocomplete / typeahead
- Video streaming (YouTube/Netflix)
- Ride-sharing (Uber/Lyft)
- Payment system
- Distributed key-value store
- Distributed job scheduler

## Template for each case study
1. **Requirements** (functional + non-functional)
2. **Scale estimates** (QPS, storage, bandwidth)
3. **API design**
4. **High-level architecture** (diagram)
5. **Data model & storage choices**
6. **Deep dives** (hot paths, bottlenecks)
7. **Bottlenecks & scaling**
8. **Failure handling**
9. **Trade-offs**
